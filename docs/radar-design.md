# 行业雷达 · 真多 Agent 周报设计蓝图

> 目标：把"行业雷达"从"自动产出的信息流水线"升级为**真正活的多 Agent 协作 + 整库联动 + 自驱提升**。
> 范围：**只重构"行业雷达"模块**（周报 / daily+weekly / 关键词覆盖 / 过程日志）。不动主题、首页、其他栏目。

---

## 0. 原则
1. **Agent 是活的**：发言、判断、博弈都由 Agent 自决，不是固定模板。
2. **整库联动**：分析要跨你全部知识库栏目，落点是你该补/该学什么。
3. **博弈即内核**：信任/信誉机制保留并强化，让它**真正影响产出**。
4. **为人服务**：周报是给你自己看的，口径 = 国内 60-70% + 可读 + 有观点。

---

## 1. 角色 + 性格（沿用原设定）
| 角色 | 人设 | 在周报中的位置（自决） |
|---|---|---|
| 采集师 | 热情侦察兵·宁缺毋滥·采纳率是命脉 | 本周扫描（素材+来源+国内外占比） |
| 核查师 | 质量教练·带建议打回·认可进步 | 素材质量把关、点名高/低质素材 |
| 分析师 | 大局观·"别人说不出来"·敢下判断 | 深度解读 + 可自主插入锐评 |
| 编辑师 | 艺术家/故事讲述·可读性底线·有编辑备注 | 引言、要闻速览、版面、编辑备注 |
| 记忆管理师 | 理性·最少规则·主持环评·维护规则信誉 | 知识库联动、规则/信誉变更、月度评审 |

**自决发言**：每个 Agent 输出 `speak: true/false` + `speak_at: <块>`，自己判断"这周要不要说话、在哪说"。不是强制每人发言。

---

## 2. 多 Agent 博弈机制（保留并强化）
- **消息协议**：REJECT/REQUEST/DISPUTE/NOTIFY/ESCALATE/CONFIRM/APPROVE/GUIDANCE/COMMAND/DIRECTIVE/PRIORITY_OVERRIDE/INQUIRE/INFO（带去重的消息总线）。
- **提交-质检-申诉-仲裁**：采集→核查（approve/reject 带建议）→ 被拒可 DISPUTE → 记忆管理师终审。
- **规则体系**：采集/核查/排版/通信/质量/信誉 六规则 + CHANGELOG。
- **复盘→（改）月度**：质量分（completeness/accuracy/depth/readability）+ strengths/weaknesses/root_cause + 规则修改 + 信誉调整。

---

## 3. 改进版信誉分（核心改动）

### 现状问题
- 单一分数 + 一句 `reason`，只看"游戏内部权重"（源排序），**不驱动内容质量**；
- 历史不透明、无衰减、多维度混在一个数里；易被"自报"刷分。

### V2 设计
**① 多维度**（每角色拆成可观测的维度，`0-100`）：
| 角色 | 维度 |
|---|---|
| 采集师 | `value`价值命中(采纳率) · `diversity`国内外/多领域覆盖 · `precision`精度(被误打回率) |
| 核查师 | `discernment`甄别(打回后续确为低质) · `coach`建议可操作性(被采纳) · `fairness`误伤率 |
| 分析师 | `insight`被编辑采信的锐评/解读占比 · `validity`事后验证 · `cross_kb`整库联动深度 |
| 编辑师 | `readability`(结构/字数/可读) · `fidelity`不歪曲/可追溯 · `edit_intent`编辑备注质量 |
| 记忆管理师 | `rule_benefit`规则变更正/负收益 · `arb_fair`仲裁公正 · `stability`规则变更频率合理 |

**② 证据链**：每次 delta 绑定**具体证据**（素材 id / 消息 id / 被采用的 insight / 规则变更 id），可审计，不写空 reason。

**③ 驱动产出（最关键）**：权重函数把信誉换算成"采信度"——
- 分析师 `insight` 越高 → 其锐评/解读在最终稿越靠前/越被保留；
- 核查师 `discernment` 越高 → 相关来源越被信任；
- 某维度低 → 该角色声音在最终稿**弱化但仍透明展示**（不隐藏，只降权）。
让博弈**真的改变内容**，而不只是内部排序。

**④ 衰减**：近期 delta 权重高于久远（半衰期，近 N 周主导）。

**⑤ 防刷/交叉验证**：delta 由**他人观察到的结果**产生（"编辑师实际用了分析师的 insight"由编辑师记录；"核查师打回的确实低质"由下游判断），记忆管理师裁决争议。禁止自报膨胀。

**⑥ 边界+透明**：0-100，`watch` 近 5 次变更，周报页脚/月评审展示。

## 4. 周报流水线（周一自动，收过去 7 天）
```
采集师(联网 web_search + RSS, 国内占60-70%)
  → 核查师(质检/打回/建议)
  → 分析师(深度解读 + 自主锐评 + 跨全库联动)
  → 编辑师(编排成"你愿意读"的周报, 1500-2000字)
  → 记忆管理师(记录已覆盖/缺口/知识库联动, 维护规则信誉)
→ 周报产出到 docs/weekly/ ; 过程日志到 docs/logs/
```
- **周末（周一）**自动；**国内内容占比 60-70%**。

---

## 5. 月度评审（每 4 份周报后）
- 记忆管理师主持：汇总 4 份周报 + 对应过程日志，评"哪份最有价值、哪个锐评说中了"。
- 评分（客观信号）：信息增量 / 整库关联度 / 国内外覆盖 / 可读性 / 低质剔除。
- **回喂**：调采集词/关键词权重/锐评角度/口径；据此更新信誉分。

---

## 6. 前端重构（仅行业雷达）
- 周报页：按 Agent 分块（扫描/解读/锐评/素材质量/知识库联动/编辑备注），视觉区分。
- 关键词覆盖页：**合并两套关键词**（sources.json 12 类 vs keywords.md 274词/10类）+ 国内外占比可视化。
- 过程日志页：从周报可点进看本周日志（过程可溯源）。
- 原页面：`daily/`、`weekly`、`logs` 旧内容 → **「历史档案」**归档；过程日志**保留**（作为多 Agent 证据链）。

---

## 7. DSH 技术实现
- **角色 = DSH 技能**（`skills/`，装在 `~/.dsh/skills`），保留人设 + 自决发言 + 结构化输出（含 speak 决策、message 协议、reputation 交互）。
- **编排 = DSH workflow**（phase/pipeline/parallel + JSON schema 校验 + 单步失败降级）。
- **运行 = 阿里云服务器常驻 dsh headless**，周一 cron 触发；repo 的 GH Actions 只负责 VitePress 构建 + 部署。
- **信誉 = 持久结构化 JSON**（多维护度 + 证据链 + 衰减），供编排方在使用时读取/写入。
